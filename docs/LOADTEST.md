# Навантажувальне тестування

Сценарій: [loadtest/smartbite.js](../loadtest/smartbite.js) (k6).

## Запуск

```bash
k6 run -e BASE_URL=$(terraform -chdir=terraform output -raw app_url) loadtest/smartbite.js
```

Параметри (`-e NAME=value`):

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `BASE_URL` | — | адреса ALB (обов'язково) |
| `VUS` | 8 | N, кількість користувачів на сталому навантаженні |
| `CACHE` | `on` | `off` додає `X-Cache-Bypass: 1`, тобто прогін без кешу |
| `THINK` | 1 | пауза між діями користувача, с (випадково 0.5×–1.5×) |
| `RAMP_UP` / `STEADY` / `RAMP_DOWN` | 3m / 5m / 2m | тривалість фаз |

## Профіль навантаження: «мало записів, багато читань»

Один віртуальний користувач у циклі робить **1 запис і 9 читань** (1:9):

| # | Операція | Тип |
|---|---|---|
| 1 | `POST /generate-plan`: згенерувати і зберегти план | запис |
| 2 | `GET /plans`: список планів | читання |
| 3 | `GET /plans/{id}`: **щойно створений** план | читання |
| 4 | `GET /ingredients`: довідник інгредієнтів (аналог «даних автора») | читання |
| 5 | `GET /plans` | читання |
| 6 | `GET /plans/{id}`: випадковий план зі списку | читання |
| 7 | `GET /plans` | читання |
| 8 | `GET /plans/{id}`: щойно створений | читання |
| 9 | `GET /plans` | читання |
| 10 | `GET /plans/{id}`: випадковий зі списку | читання |

Між діями пауза ~1 с (think time). Без неї кожен віртуальний користувач слав би запити
без зупинки, і це вже не відповідало б поведінці реальних людей.

Фази (`ramping-vus`): **0→N за 3 хв → N протягом 5 хв → N→0 за 2 хв**, разом 10 хв.
Поступове наростання дає автоскейлеру час відреагувати і показує, при якому
навантаженні сервіс починає деградувати. Стрибок одразу до N виміряв би лише холодний старт.

### Вибір N

Один цикл ≈ 10 дій × (~1 с паузи + час відповіді), тобто ≈ 12–15 с, отже
≈ 0.07 запису/с на користувача. Один запис коштує ≈ 0.3 с CPU повного ядра, а задача
має 0.25 vCPU. Тому **N = 8** дає ≈ 0.55 запису/с і ≈ 0.17 ядра. Для однієї задачі
це помітно більше за ціль 60 %, і автоскейлер має дійти до 2–3 задач.
Якщо масштабування не спрацювало, збільште N (`-e VUS=12`). Якщо з'являються помилки
ще до масштабування, зменште N.
